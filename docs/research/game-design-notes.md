## 1. Juice（手触り）— 動きと音が無いゲームは死んでいる

- 出典: https://abagames.github.io/joys-of-small-game-development-en/make_game_juicy.html（2026-08-29 確認）
- 事実: 小規模ゲーム向けの juice 技法として、色数の工夫・トゥイーン/イージング・
  イベントに応じた拡縮バウンス・効果音と音楽・多数パーティクル（煙/破壊/軌跡）・
  画面揺れ・キャラの目や表情・**被弾時のヒットストップとノックバック**を列挙。
  開発時間が限られるときはパーティクルと音だけでも効果的、と明記。
- 事実: 元ネタは Jonasson & Purho の講演「Juice it or lose it」（Nordic Game Jam
  2012）。凡庸なブロック崩しに演出を足すだけで生き返る実演。Vlambeer の
  「The Art of Screenshake」は揺れの原則として「爆発や重い一撃でカメラを数 px
  蹴り、素早く減衰。イベントの重さに揺れを比例させる」。
  （出典: https://www.gamedeveloper.com/design/squeezing-more-juice-out-of-your-game-design- 2026-08-29 確認）
- 学び: SIDRA の 4 テンプレには音が 1 つも無く、揺れ・ヒットストップも無い。
  **最小の投資で最大の体感差が出るのは音 → 揺れ/ヒットストップ → パーティクル の順。**
- SIDRA での反映先: C-1017（効果音）/ C-1020（揺れ・ヒットストップ・粒子）**→ 反映済み 2026-08-29（C-1020 完了: 重さ比例の画面揺れ・被弾/撃破のヒットストップ・草刈り/宝石/命中の粒子を 4 テンプレ全部に配線。reduced-motion で揺れと粒子は 0、ヒットストップは残す）**

## 2. 効果音はブラウザ内で合成できる（外部ファイル不要）

- 出典: https://sfxr.me/ ・ https://github.com/chr15m/jsfxr（2026-08-29 確認）
- 事実: sfxr（DrPetter 作）系のレトロ効果音は、波形種別＋ADSR エンベロープ
  （attack/sustain/punch/decay）＋周波数（基準/傾き）＋ビブラート＋デューティ比＋
  ローパス/ハイパスの少数パラメータで合成される。定番プリセット名は
  pickupCoin / laserShoot / explosion / powerUp / hitHurt / jump / blipSelect。
  jsfxr はこれを Web Audio API で再生する JS ライブラリ。
- 学び: プリセットの正体は「オシレータ＋短いエンベロープ」なので、**ライブラリを
  入れなくても Web Audio の OscillatorNode + GainNode で同等の 8bit 風 SFX を
  数十行で自作できる**（SIDRA の自己完結・外部取得なしの原則と両立）。
  ブラウザの自動再生制限があるため、AudioContext は最初のユーザー操作で resume する。
- SIDRA での反映先: C-1017（creation/audio.py として自作合成。jsfxr のコードは
  移植しない＝パラメータ設計の考え方のみ参考）**→ 反映済み 2026-08-29（C-1017 完了、12 種の SFX を 4 テンプレに配線）**

## 3. ロック＆キー構造（ゼルダ型の骨格）

- 出典: https://www.boristhebrave.com/2021/02/27/lock-and-key-dungeons/（2026-08-29 確認）
- 事実: ロックは進行を止めるもの、キーはそれを解くもの。種類は物理アイテムに
  限らず、道具（爆弾/矢）・能力アップグレード・知識（パスワード）・イベントフラグ。
  hard（正規手段でしか開かない）と soft（上手い人は迂回できる）の区別がある。
  依存関係は mission graph（A を開けないと B に行けない）で表せる。
  一本道でなく**複数の経路と任意の探索報酬**があるときに面白くなる。
- 事実: 現代ゼルダの単純化形は「並列の 4〜5 部屋を解く→ボス鍵→ボス」。
  Mark Brown（GMTK）の Boss Keys 図法は小鍵/扉/ボス鍵を記号化して物理配置と
  論理進行を同時に描く。（出典: https://www.patreon.com/posts/how-my-boss-key-13801754 ほか 2026-08-29 確認）
- 学び: SIDRA の adventure は「鍵 1 個の完全一本道」= mission graph が線 1 本。
  **面白さの最低条件は「分岐 1 つ＋任意報酬 1 つ」から。**部屋テンプレを増やす
  よりも、同じ 3 部屋の中に「開けなくてもよい扉」を足す方が効く。
- SIDRA での反映先: C-1021（分岐と任意報酬）/ 将来の部屋数拡張**→ 反映済み 2026-08-29（C-1021 完了: 洞窟に「開けなくてもよい扉」1 つ＋その奥に護符。扉以外に入口が無いことを実際に世界を build して確認）**

## 4. 視認性・アクセシビリティ（読める画面の最低条件）

- 出典: https://gameaccessibilityguidelines.com/basic/（2026-08-29 確認）
- 事実: 基本ガイドラインとして「テキスト/UI と背景に高いコントラスト」
  「**固定の色だけで本質情報を伝えない**（形・パターン・文字を併用）」
  「タッチ画面では操作要素を大きく・間隔を空けて」「操作の再割り当てを許す」
  「明滅と反復パターンを避ける」。
- 事実: モバイルのタッチ目標は最低 48x48dp・間隔 8dp が業界標準。
  （出典: https://www.gamedeveloper.com/game-platforms/accessibility-heuristics-and-evaluation-criteria-for-mobile-games 2026-08-29 確認）
- 学び: adventure の壁と床は同系色で「色だけ」の区別＝ガイドライン違反そのもの。
  壁には輪郭と明度差、ドアには形のある標識が要る。スマホの移動手段が無いのは
  タッチ操作ガイドライン以前の欠落。
- SIDRA での反映先: C-1018（コントラスト・ドア標識・水配置）**→ 反映済み 2026-08-29（C-1018 完了: 壁に縁の形・扉にシェブロン・池を実配置）** / C-1019（仮想パッド、
  48dp 以上・reduced-motion と両立）**→ 反映済み 2026-08-29（C-1019 完了: 56px の
  ボタンを 12px 間隔で canvas 内に描画。合成 KeyboardEvent でテンプレ側の
  キーボード処理をそのまま駆動するので、新テンプレは書いた日から指で遊べる）**

## 5. 収集要素には使い道（シンク）が必須

- 出典: https://www.gamedeveloper.com/design/opinion-collectible-intent ・
  https://game-wisdom.com/critical/collectible-design-videogames ・
  https://300mind.studio/blog/what-is-game-economy-design/（いずれも 2026-08-29 確認）
- 事実: 収集物に意味のあるゲーム内目的が無ければ、プレイヤーは収集物どころか
  ゲーム自体への興味を失う。経済設計では tap（資源の入口）と sink（出口）の
  釣り合いが基本。収集を始めさせるには資源やボーナス体力など外的動機が要る。
- 学び: SIDRA の宝石は tap だけあって sink が無い（数字が増えるだけ）。
  **最小の sink は「宝石 n 個でハート回復/最大+1」**。これだけで草刈りに理由が生まれる。
- SIDRA での反映先: C-1021（宝石の使い道）**→ 反映済み 2026-08-29（C-1021 完了: 祠で宝石 3 個 → 最大ハート +1。宝石は tap だけだったのが 2 か所の sink を持った）**

## 6. 巨大ボス演出の文法（社長提供の映像を全編視聴して抽出）

- 出典: 社長所有 DVD の私的視聴（2026-08-31、『スター・ウォーズ／クローン・
  ウォーズ』の巨大生物回・22 分 29 秒を全編コマ送りで確認）。URL なし。
  以下は**映像の複製ではなく視聴して読み取った設計上の観察**。キャラ・名称・
  素材は C-0e 冒頭の決まりどおり生成物に使わない。
- 観察 1: **巨大さは「全身を見せない」ことで作られる。**怪獣は脚・尻尾・爪が
  画面を横切る部分描写が基本で、全身の引きは要所に 1 回だけ。小さい存在
  （兵士・戦車）と同じフレームに入れて対比する。カメラは低い。
- 観察 2: **重さは歩幅と土煙。**多脚戦車は脚の周期が遅く、接地のたびに土煙。
  被弾は「閃光 1 拍 → 煙が残る → シルエットが煙から再登場」の 3 段。
- 観察 3: **エスカレーションの型**: 作戦説明（ホロ卓）→ 部隊前進 → 予期せぬ
  覚醒（地割れが走る→兵が走って逃げる→塵の壁に呑まれる）→ 引きの 1 枚で
  規模提示 → 反応ショット（操縦席の顔）を挟んで再加速。
- 観察 4（実測）: **戦闘の音圧は平常より段違いに高い。**20 秒窓の平均ラウド
  ネスを全編測ったところ、戦闘窓は -13.8〜-16.5 LUFS に集中し、会話場面より
  明確に大きい。ゲームでも「戦闘中は音の密度を上げる」は音量差で作れる。
- 学び: SIDRA には**ボス戦という概念が無い**（敵は等身大の量産型のみ）。
  部分描写・遅い周期・土煙・段階（phase）・反応の間、は全部いまの canvas
  技術で再現可能。ブリーフィング（ホロ卓）は開始画面の強化形。
- 定量（2026-08-31 追加・**0.1 秒ごと全 13,487 コマを機械走査**して抽出。
  カット検出はコマ間輝度差分の突出、閃光は輝度の急騰と復帰で定義）:
  - カット数 308 / 22.5 分（平均ショット長 4.4 秒）
  - **戦闘のショット長 中央値 2.1 秒、会話 4.4 秒**——戦闘はカットが 2 倍速い。
    ゲームでは「戦闘中はイベント（攻撃・予兆・被弾）の間隔を約 2 秒に刻む」が
    このリズムの移植になる
  - **閃光は 13 回、半減まで中央値 0.20 秒**——SIDRA の現行 flash 減衰
    （1 フレーム 0.05、60fps で半減 0.17 秒）は**実測とほぼ一致**。既存値を
    根拠づける実測が取れた（変更不要）
  - **コマ間の動きは戦闘が会話の 2.9 倍**——C-1034 の音圧差と合わせ、
    「戦闘は音も動きも約 3 倍」が演出の基準値
  - 動き最大の 2 点はタイトルロゴとエンドロール（文字スクロール）で、
    ゲーム設計には非該当と判定
- SIDRA での反映先: C-1032（巨大ボステンプレ）/ C-1033（作戦説明つき開始画面）/
  C-1034（戦闘時の音圧差）**→ 反映済み 2026-08-30（ループA が 3 件とも完了:
  kaiju テンプレ＝7 本目・全 7 テンプレにブリーフィング開始画面・戦闘中の
  音圧段上げ。実測値 2.1 秒間隔／閃光半減 0.2 秒／戦闘 3 倍はそのまま採用された）**

## 7. グラフィックと構成（同映像の第 3 弾: 配色と場面の組み立てを機械抽出）

- 出典: §6 と同じ社長所有 DVD の私的視聴（2026-09-01 追加分析。社長指示
  「グラフィックとか、あと構成などを意識してインプット」）。URL なし。
  45 秒間隔の全 30 場面から代表 10 場面を選び、各フレームの**主要 4 色を
  MEDIANCUT 量子化で機械抽出**した。以下は色の数値と設計上の観察のみで、
  映像の複製は含まない。
- 実測（場面ごとの主要 4 色。時刻は本編内）:

  | 場面 | 時刻 | 主要 4 色 |
  |---|---|---|
  | 導入 | 0:10 | `#000000 #010001 #020202 #000002` |
  | 戦場・前進 | 1:35 | `#2f282f #010101 #554e55 #161019` |
  | 戦闘ピーク | 3:08 | `#453139 #020101 #2b1e25 #6f5159` |
  | 切り札投入 | 4:37 | `#181317 #010001 #33272d #654d56` |
  | 覚醒・霧 | 8:20 | `#2d1f26 #594354 #020202 #987a99` |
  | 怪獣対峙 | 10:33 | `#c9a2c8 #3d293b #020001 #896684` |
  | 会議 | 13:31 | `#161112 #0a0709 #000000 #46372e` |
  | ホロ卓 | 14:15 | `#151112 #000000 #090607 #2f3745` |
  | 夜の街 | 20:11 | `#27222a #151218 #3c3740 #010101` |
  | 終盤の顔 | 21:40 | `#190f0e #000000 #0f0807 #463022` |

- 観察 5（配色の設計）: **土台は全編ほぼ同じ「暗い無彩色」で、場所ごとに
  アクセント 1 系統だけを載せ替えている。**戦場は埃っぽい藤紫
  （`#554e55`/`#6f5159`）、会議室は暗い琥珀（`#46372e`）、ホロ卓は鋼青
  （`#2f3745`）、夜の街は青紫灰。**色相を見れば場所が分かる**＝色が場面の
  ラベルとして機能している。
- 観察 6（明度の予約）: **全編で最も明るいパレットは怪獣対峙（`#c9a2c8`）。**
  導入と会話場面を意図的に暗く保つことで、クライマックスの霧と逆光の明るさが
  最大の見せ場になる。明るさは常時使うものではなく**山場のために取っておく資源**。
- 観察 7（奥行き）: 遠景は霧・煙・塵のレイヤで一段ずつ淡くなる（色ではなく
  **コントラスト差で距離を描く**）。巨大さの部分描写（§6 観察 1）と併用され、
  手前のシルエット・中景の被写体・奥の霞の 3 層が基本形。
- 観察 8（構成＝お話の組み立て。ショット長×音圧×輝度の全編データから）:
  22.5 分は**動と静の交互の波**でできている——導入(〜2:00) → 戦闘第 1 波
  (2:00-5:30) → 静(会話) → 覚醒・戦闘第 2 波(8:20-11:30) → **政治・会議の長い谷
  (11:30-16:30)** → 再上昇 → 最終戦(19:00-20:30) → 終幕の静。山は 3 回で
  2 回目が最大（怪獣対峙）。**静の谷が長いほど次の山が大きく感じられる**——
  C-1034 で入れた「戦闘だけ音を上げる」と同じ原理の、場面スケール版。
- 学び: SIDRA の adventure は 3 部屋とも同じパレット、kaiju も 1 枚の背景で
  戦い続ける。**「場面が変われば基調色が変わる」「クライマックスに最大明度を
  予約する」の 2 規則が丸ごと欠けている。**構成側は C-1032 の phase 制と
  C-1033 のブリーフィングで波の骨格は入ったので、残る欠落は色の側。
- SIDRA での反映先: C-1036（場面ごとの環境パレット）
